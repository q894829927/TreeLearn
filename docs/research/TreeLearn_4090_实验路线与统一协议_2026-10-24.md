# 第一部分：研究主计划（实际执行时先读这里）

## 1. 研究目标：要做什么？

**拟定论文方向：面向复杂森林点云的几何一致性与可靠性感知单木实例分割。**

采用现有 TreeLearn 网络与数据处理流程，研究两个可能的性能瓶颈：

- **创新点一——几何一致性 Offset 学习：**原始 TreeLearn 逐点预测树基部的三维偏移量。研究如何约束同一树的预测终点更稳定、不同树更易分开，重点降低邻树合并与单树拆分。
- **创新点二——可靠性感知实例聚类：**原始 TreeLearn 使用语义概率、垂直性和 Offset 高度约束筛选候选种子，再用 HDBSCAN 聚类。研究能否预测点的 **XY Offset 可靠性**，筛出更适合聚类的核心点，减少错误聚类，同时保留稀疏小树。

**可选扩展：**如果最终错误分析显示树冠点在 5-NN 分配阶段存在明显错误，再考虑利用网络特征与实例原型做树冠归属；**不是硕士论文必须实现的第三个创新点**。

**评价目标：**在相同数据、训练预算、网络主干、预测滑窗和评测脚本下，相较原始 TreeLearn 提高检测 F1、Coverage 或实例边界质量；同时记录小树召回、耗时与显存。创新有效性由实际实验决定，不预先承诺固定百分比提升。

## 2. 整体流程：只分四个阶段

| 阶段 | 任务 | 产物 | 进入下一阶段的条件 |
|---|---|---|---|
| **阶段一：准备** | 检查已有数据和 HAIS；确定训练、验证、测试数据；跑几批训练检查程序 | 冻结的数据清单、训练配置 | 数据不混用，程序能前向、反向与保存 |
| **阶段二：原始模型** | 从 HAIS **重新训练 noisy**；从本轮 noisy **微调 mid** | 新的 TreeLearn 原始基线 checkpoint | 独立验证集有可靠结果 |
| **阶段三：创新实验** | 先在训练/验证数据上分析错误；实现创新一、创新二，比较各自收益 | 改进模型、消融记录 | 同协议下能够公平比较 |
| **阶段四：评价与论文** | 固定最终模型；评估 L1W 和 Wytham；整理图表、失败案例与论文章节 | 对比表、消融表、可视化、论文 | 结果可追溯、局限性明确 |

**原则：**先训练基线，再研究创新。不要因为技术附录写了许多可能的修复和对照，就在正式训练前开展无休止的工程重构。

### 3.1 本轮明确的数据划分

\`\`\`text
noisy train:   18 片自动标注森林 → 已有合格 25,000 Crop 优先复用
mid train:     FOR-instance 选定 plots（排除 NIBIO plot16）+ LAUTx
validation:    NIBIO plot16（若缺失，先找独立的其他验证区并明确另立协议）
test:          L1W
cross-domain:  Wytham Woods
\`\`\`

**重要的两个排除规则：**

1. 目前仓库 [configs/data_gen/gen_val_data.yaml](../../configs/data_gen/gen_val_data.yaml) 的 \`forest_path\` 是 \`data/val/forest/L1W.laz\`，[dataset_test.yaml](../../configs/_modular/dataset_test.yaml) 则默认读取 \`data/val/tiles/npz\`。用户先前提供的本地审查称，该目录内有 **323 个 L1W Tile**。**本轮训练不能沿用这一默认验证目录**，必须显式指向独立验证数据。
2. NIBIO plot16 需要按**原始 plot 身份**排除，不能只排除某个文件名：FOR-instance train/val/test 中如果包含 plot16，必须排除对应完整森林及全部裁剪、重命名副本和缓存。最终用 plot_id/crop_source 的交集检查验证其不存在于训练集。

**Wytham 的定义：**以前使用其他 TreeLearn 模型评价 Wytham，不等于本轮重新训练发生了数据泄漏；本轮可将其设为独立留出跨域测试。论文应披露已有历史认识，不称为研究者完全未见过的首次盲测。为避免历史反馈进一步影响方法选择，本轮不使用 Wytham 的结果决定创新点参数。

### 3.2 25,000 个 Crop 的处理规则

**已有且合格 → 直接用；缺失、损坏或格式/划分不兼容 → 才按当前代码生成。**

最低检查只需确认：实际文件数量和可加载性，NPZ 中 \`points\`、\`feat\`、\`instance_label\` 等字段，来自正确的 18 片森林，标签规则正确（-1 忽略、0 非树、正整数为单木实例），没有训练/验证林地交叉，Crop 预处理与当前代码兼容。检查通过后将文件路径和清单冻结；E0～E3 使用同一份训练数据。

如果现有 Crop 来自另一套 PTv3 数据管线，不能仅凭其 \`verified\` 标志判断可复用；须核对 TreeLearn 需要的字段与预处理。**不要求为了“全新研究”而重复生产完全相同的数据文件。**

### 3.3 如果 mid 数据暂时不齐

先完成阶段一和 noisy 训练。FOR-instance / LAUTx 可以在 noisy 训练期间准备。允许先对 noisy 结果进行工程验证和初步分析，但**不将 noisy 与 mid 的不同训练设置作为公平的创新对照**。

## 4. 训练与分割协议：以当前 main 代码为准

本项目不是逐参数复刻 2024 年论文的旧实现。**固定现有代码的可执行参数**；只有正式登记为创新点的部分才允许在实验组中变化。

| 参数 | 本轮统一基线 |
|---|---|
| 网络 | 当前稀疏 3D U-Net、Semantic Head、Offset Head；初始通道 32 |
| 模型输入 | 保留 \`configs/_modular/model.yaml\` 的默认 feature/coord 开关 |
| 体素与 Crop | 0.1m 体素；35m × 35m Crop，训练中心 8m × 8m |
| 原始损失 | \`50 × semantic CE + mean Offset L2\` |
| Offset 真值 | 当前 \`TreeDataset.getOffset()\` 的低位约 0.5m 树基部定义，不改回论文旧的约 3m 规则 |
| noisy 配置 | batch 2、1000 epochs、每 epoch 500 examples，理论上约 250,000 次 batch 参数更新尝试 |
| noisy 优化器 | AdamW，lr 0.003，weight_decay 0.001，当前余弦调度与 50 epoch warm-up |
| noisy 初始化 | \`data/model_weights/hais_ckpt_spconv2.pth\`；**不是之前训练的 TreeLearn 模型** |
| mid 配置 | 从本轮 noisy checkpoint 出发；暂按目标约 12,500 更新尝试（500 examples/epoch、batch 2 约 50 epochs），lr 0.0005，最终配置在启动前固定 |
| 推理 | 35m 滑窗，中心 8m，stride 4m；重叠点按当前代码融合 |
| 种子筛选 | P(tree)≥0.5，verticality>0.6，\`abs(offset_z)<4\` |
| 聚类 | **HDBSCAN，min_cluster_size=50**，对 Offset 后 XY 进行聚类 |
| 剩余树点归属 | 在 Offset 后的 3D 坐标上执行 **5-NN** |
| 评价 | 当前 \`evaluate.py\`；Hungarian 匹配，IoU 严格大于 0.5；检测 F1、Omission、Commission、Coverage |

**与论文旧参数不一致的地方：**论文的 noisy 更新次数、树基部定义、聚类方法及最小簇、tau_off、KNN 的设置曾与当前代码不同；本次都以当前 main 为准，不把论文数值和当前程序数值混成一个“完全复现”。

**对训练步数的实事求是表述：**现有循环是按 epoch 结束、调度器按 epoch 变化，并且 AMP GradScaler 可能跳过参数更新。所以 \`250,000\` 和 \`12,500\` 首先是**配置预算的近似换算**，不能在未检测实际更新数之前称为“严格完成的成功 optimizer steps”。如果改成成功更新数控制停止，需要在正式训练前统一应用于基线和创新组，并留下变更记录。

## 5. 第二阶段：怎样重新训练 Baseline？

\`\`\`text
HAIS 公共初始化权重
        ↓
训练原始 TreeLearn noisy（18 片森林 + 25,000 合格 Crop）
        ↓
本轮新 noisy checkpoint（C0）
        ↓
训练原始 TreeLearn mid（FOR-instance 非 plot16 + LAUTx）
        ↓
本轮新 mid checkpoint（E0 / Baseline）
\`\`\`

- **C0：**从 HAIS 初始化开始新训练，不接续旧 noisy、with-small、历史 s43 或其他历史 TreeLearn 权重。
- **E0：**从本次 C0 初始化并完成原始 mid 微调，得到**主要论文对照模型**。
- **最佳权重：**只根据隔离的验证集（例如 NIBIO plot16）的预先固定准则确定，主训练器当前提供验证 Offset MAE 与 Semantic Accuracy；不使用 L1W 或 Wytham F1 选模型。
- **统一训练协议：**后续 E1/E2/E3 各自从**同一个本轮 C0 checkpoint**独立开始 mid 训练，不是从 E0 训练结束继续延长。共同使用相同训练 Crop、数据划分、基础增强、batch、epoch/实际更新预算、验证与评测。
- **最小训练检查：**开始长训练前用几批数据检查网络可前向、损失可反传、HAIS 可正确加载、训练可以保存及恢复一次。若发现确定的 AMP 梯度裁剪或恢复 Bug，先统一修正所有受控实验，再启动正式 C0；不需要先开发完整科研管理平台。

**执行入口（当前仓库）：**训练 [tools/training/train.py](../../tools/training/train.py)、原始配置 [configs/training/train.yaml](../../configs/training/train.yaml)，推理 [tools/pipeline/pipeline.py](../../tools/pipeline/pipeline.py)、原始推理配置 [configs/pipeline/pipeline.yaml](../../configs/pipeline/pipeline.yaml)，评价 [tools/evaluation/evaluate.py](../../tools/evaluation/evaluate.py)。下一步会把本轮完整配置放到 \`configs/research/\`，**不直接改写旧的默认配置**。

## 6. 第三阶段：主要创新怎么做？

### 创新点一：几何一致性 Offset 学习（E1）

**问题：**原始 Offset L2 追求每个点偏移预测正确，但不直接衡量“同树偏移终点是否形成紧凑、可分离的聚类”。大树树冠、冠层重叠、树干接近时，点级平均误差小也可能被 HDBSCAN 误合并。

**初始方案：**在不修改稀疏 U-Net 主干的前提下，在原损失上增加：
- **Direction Loss：**预测 Offset 与真实 Offset 方向一致，避免长距离树冠点向错误方向漂移。
- **Instance Compactness Loss：**同一棵树偏移后的点应靠近该树的监督基部位置，并按实例均衡，避免大树占据全部损失权重。
- **Local Separation（可选）：**若 P0 证明确有邻树融合问题，再考虑相邻实例分离约束，不一开始就加复杂损失。

**创新价值须验证，而非预设：**并非“加入方向损失”本身必然新颖，而是测试**与下游 HDBSCAN 可分性相关的实例几何约束**是否真正改善森林单木分割，尤其是相邻树合并率、分裂率、Coverage 和小树召回。最终方法必须与只加 Direction、只加 Compactness 的简单对照比较。

### 创新点二：可靠性感知种子聚类（E2）

**问题：**当前聚类依据固定规则从语义树点中筛选种子，但是部分候选点的 Offset 在 XY 上不可靠，可能造成邻树混合或簇结构不稳定。

**初始方案：**
1. 使用现有主干点特征增加一个轻量的 **Offset XY 残差/可靠性预测头**。优先预测 \`||offset_xy_pred - offset_xy_gt||\` 的尺度，不假定可靠性分数天然是“正确概率”。
2. **只对满足原几何条件的种子候选集合 M0** 评价与使用这一可靠性；把高可靠候选提供给现有 HDBSCAN（保留 XY 聚类、最小簇 50）。
3. 防止小树因核心种子稀疏而消失。可靠种子筛选若漏掉小树，可尝试简单的第二轮补簇/回退到原始筛选，不一开始就引入复杂原型学习。
4. 必须与**相同保留比例**的随机筛选、按语义概率排序筛选、原始筛选比较，排除仅通过减少候选点就提升成绩的解释。

**重点不是全树点 XYZ 残差相关性，而是 M0 集合内 XY 可靠性对聚类纯度、覆盖率与最终实例 F1/Coverage 的实际帮助。**

### 可选：树冠归属细化

如果错误诊断发现最后 5-NN 将大量冠层点分错树，可用已有 32 维网络特征建立实例原型，结合偏移空间距离重分配少量不确定点；先对比原始 5-NN 与距离加权 KNN。**在证明 5-NN 是明显瓶颈前不做。**

## 7. 四组核心实验（够用，额外消融按结果增加）

| 实验编号 | 内容 | 初始化和训练规则 | 要回答的问题 |
|---|---|---|---|
| **E0** | 原始 TreeLearn mid | 同一个本轮 C0 noisy checkpoint，原始损失与后处理 | 原始基线是多少？ |
| **E1** | E0 + 创新点一 | 从相同 C0 独立微调，同数据/预算；只改变几何损失 | 几何约束是否有效？ |
| **E2** | E0 + 创新点二 | 从相同 C0 独立微调，同数据/预算；新增轻量可靠性头/种子策略 | 可靠性聚类是否有效？ |
| **E3** | E0 + 两个创新点 | 从相同 C0 独立微调，同数据/预算；同时加入两项 | 两个创新是否互补？ |

**C0 只是本轮 noisy 公共初始化，不是 E0～E3 之外还必须做的四个论文算法实验。**

基本消融：E1 对照 Direction-only / Compactness-only；E2 对照原筛选 / 随机筛点 / 语义排序筛点；E3 对照去掉任一模块。需要时增加更多消融，不预先强制跑十几组。

**公平性说明：**E2 多一个可靠性头并不一定需要额外整网微调轮数。首版规定该头**从 C0 出发，在与 E0 等长的 mid 训练中学习**；不采用“先完整训练 E0，再额外继续训练若干 epoch”作为默认，因为这样会导致额外训练预算。若后来测试冻结 E0 仅训练新头，则应单列附加头训练成本与等预算对照，不直接混进四组主表。

**四组实验优先在隔离验证集上比较；最终 E0～E3 都按已冻结的评测协议进行 L1W/Wytham 测试。** 不根据测试成绩反复重调模块。

## 8. 第四阶段：评测与论文怎么做？

### 8.1 必需指标

采用原生 \`tools/evaluation/evaluate.py\`，保持 GT 坐标、投票/近邻传播、Hungarian 匹配及 IoU>0.5 协议一致，主表报告：
- **Detection F1、Omission、Commission**：单木是否被正确检出。
- **Coverage（每棵 GT 树最高 IoU 的平均）**：单木分割质量。
- **实例 Precision/Recall、小树召回、邻树误合并/同树拆分**：辅助解释改进点。
- **训练时间、整林推理时间、GPU/CPU 峰值内存**：单卡成本。

最终论文至少包含：E0～E3 主表、每个创新的简单消融表、可视化（正确分割/漏检/合并/拆分）、典型复杂树冠案例、局限性讨论。若有多个独立林地，应按 plot 进行配对统计；不能把同一林地的数百万点视为独立重复。单次实验的结果不要夸大为统计显著。

### 8.2 GT 使用边界

- **正式评价：**用原生评价脚本将预测树实例与单独保存的真实标签 GT 对齐；不得把推理 \`pointwise_results.npz\` 内可能是 -1 占位的 \`instance_labels/offset_labels\` 误认为真实标签。
- **需要错误诊断时才开发 GT 对齐程序：**要保存坐标中心 \`xyz_mean\` 和转换关系，区分 crop 内 getOffset 的监督基部与整林完整树 GT 基部；两者不同不能直接当模型误差。
- **数据使用：**训练/验证区可以反复分析；L1W/Wytham 的 GT 用于模型锁定后的最终评价，不用于决定模型、调权重或分割阈值。

# 第二部分：技术附录（开始相关实验时才看）

## A. 网络、监督与实现对照

**当前网络入口：**[tree_learn/model/tree_learn.py](../../tree_learn/model/tree_learn.py)，七层级稀疏卷积 U-Net，输出 semantic logits（2 类）与 Offset（3D）；网络默认输入开关见 [configs/_modular/model.yaml](../../configs/_modular/model.yaml)。

**当前训练监督：**[tree_learn/dataset/dataset.py](../../tree_learn/dataset/dataset.py) 的 \`TreeDataset.getOffset\` 计算树基部的监督 Offset。实例标签按 \`(batch_index, instance_id)\` 组合，不能合并不同 Crop 中恰巧编号相同的树；忽略点不参与有效监督。

记 \`p_i\` 为点坐标、\`o_i\` 为预测 Offset、\`o_i^*\` 为按当前代码规则得到的真实 Offset，\`b_i=p_i+o_i\` 为预测偏移终点；原损失：

\`\`\`text
L_base = 50 * CE(semantic_prediction_logits, semantic_labels, masks_sem)
       + mean_{valid tree points} ||o_i - o_i*||_2
\`\`\`

**当前推理与评价相关源码：**[tree_learn/util/pipeline.py](../../tree_learn/util/pipeline.py)、[tools/pipeline/pipeline.py](../../tools/pipeline/pipeline.py)、[tools/evaluation/evaluate.py](../../tools/evaluation/evaluate.py)。当前 \`configs/_modular/grouping.yaml\` 中 \`tau_group=0.15\`，但**默认 HDBSCAN=True 时不代表它按 0.15m 半径聚类**。

## B. 创新点一的候选数学实现

在 E1 中可以先做两种独立可消融项。

**方向项**（跳过 GT Offset 近零点，避免方向不确定）：

\`L_dir = mean_i [ 1 - cosine(o_i, o_i*) ], for ||o_i*|| > eps\`

**实例紧凑项**：对每棵有效树 \`k\`，令 \`g_k\` 为**当前 Crop 按 getOffset 计算的 GT 基部**。不使用整林另算出的基部直接替代训练 GT。令 \`S_k\` 为属于该树且监督有效的点：

\`L_comp = mean_k [ mean_{i∈S_k} Huber( ||(p_i+o_i)-g_k||_2 / (r_k+eps) ) ]\`

这里 \`g_k\` 和尺度 \`r_k\` 都从当前训练 GT 得到并不回传梯度，预测终点 \`p_i+o_i\` 回传梯度；是否使用 \`r_k\` 归一化、树的最小有效点数与权重 \`lambda_dir/lambda_comp\`，须在**第一次正式 E1 参数搜索前**用训练/验证数据冻结，不能用测试集调整。

\`L_E1 = L_base + lambda_dir * L_dir + lambda_comp * L_comp\`

**注意：**方向和紧凑项有可能与原 Offset L2 信息冗余。除 F1/Coverage 外，检查 GT 单树内预测终点散布、邻树终点间距离，以及 initial HDBSCAN 簇的纯度。若只有训练误差改善而实例指标不升，应如实报告并回退。可选 Separation 不应先于 Direction/Compactness 消融实施。

## C. 创新点二的候选实现与简单对照

**可靠性头：**\`f_i\`（当前 32 维 backbone point feature）经小 MLP 输出预测 XY Offset 残差尺度 \`s_i\`：

\`\`\`text
r_i_xy = ||(o_i - o_i*)[:2]||_2
L_quality = mean_i [ exp(-s_i) * r_i_xy + s_i ]       # 数值稳定需 clamp 或其他约束
q_i = exp(-clamp(s_i))                                # 仅是相对可靠性分数，不是概率
\`\`\`

首版 E2 在**同样的 mid 训练预算**内训练网络和新头；质量预测目标的梯度使用方式（是否 detach Offset 残差、头与主干如何联合优化）应在 E2 代码实现前固定并配套简单对照。关键是先检查**原始 HDBSCAN 候选种子 M0 内**的 \`q_i\` 与真实 XY 残差及错误种子概率是否相关，而不是只报全体点的 XYZ 相关性。

**聚类不变的主体：**仍在满足 \`P(tree)≥0.5 & verticality>0.6 & |offset_z|<4\` 的点中选种子，对偏移后的 XY 使用 HDBSCAN(min_cluster_size=50)，随后按原代码在偏移后的 3D 空间为剩余树点做 5-NN。E2 改动在于可靠性的**种子筛选**及必要的漏检补偿。

**必需的最低公平对照：**原始 M0；保留比例相同的随机种子；保留比例相同的语义置信度最高种子；可靠性最高种子。若只删点就能得到同等提升，应明确指出质量头的增量价值不足。要记录小树种子覆盖，避免提升精度却牺牲小树检出。

**跨 tile 处理：**主干点特征和质量头预测须遵循现有 tile 内预测、坐标融合，再进行全局种子选择的流程；不能让同一个实际点的不同 tile 预测未经聚合直接参与全局 HDBSCAN。

## D. 训练程序必须知道的最少工程细节

**在第一轮长训练前处理，不用独立做一个大型研发阶段。**

| 情况 | 原始代码状态 | 简单处理原则 |
|---|---|---|
| 随机性 | 训练入口未统一 seed | 先固定 Python/NumPy/PyTorch/DataLoader 的随机源并记录；至少确保受控对照一致 |
| AMP 梯度裁剪 | \`scaler.scale(loss).backward()\` 后直接 clip，未先 \`scaler.unscale_(optimizer)\` | 短训练确认并在正式训练前统一修复；所有组共同使用同一修复代码 |
| Checkpoint | 当前 \`checkpoint_save\` 仅存网络、优化器、epoch | 为长训练至少增加 scaler 与 scheduler 状态及必要 RNG 状态；验证保存→恢复不会意外重置 |
| 成功更新数 | 当前按 epoch 循环和调度；AMP 可能跳步 | 记录实际成功的 optimizer updates、AMP skip 和 LR；如果改停止条件，所有组采用同一策略 |
| 验证路径 | 当前默认 \`data/val/tiles/npz\` 可能是 L1W | 本轮配置显式指向独立验证区，禁止默认使用 |
| 大森林 GT | 推理缓存可能没有真实标签，坐标还被中心化 | 仅做错误诊断时单独对齐 GT；保存转换元数据，不直接将占位字段当标签 |
| 显存/硬盘 | 4090 24GB，完整 Crop 与森林可能很大 | 先抽样几批量测峰值，复用现有合格文件，不重复产生全量数据 |

**工程修复不是论文创新。** 如果为了正确训练而修复训练器，应在 C0 开训前定稿，然后原始基线及所有创新组都使用同一训练实现。不要在训练完 E0 后单独修复 E1 的优化语义。
