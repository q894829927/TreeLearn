## 0. 总目标、研究问题与成功条件

以 TreeLearn 为基线，在**单张 RTX 4090（24GB VRAM）**上研究复杂森林点云的单木实例分割。固定稀疏 U-Net 主干、训练数据划分、体素与滑窗规格、原生评测协议，分阶段测试下列科学问题：

- **RQ1：**仅依赖逐点 Offset 欧氏距离回归，是否忽略了单木实例内部的预测一致性以及邻树之间的可分性？几何一致性监督能否在不增加主干参数的情况下改善偏移聚类？
- **RQ2：**网络能否从现有 32 维点特征估计偏移的不可靠程度？该估计能否提升种子点筛选，而不损害小树检出？
- **RQ3：**在固定 HDBSCAN 设置下，利用可靠种子与实例原型进行剩余树冠点归属，能否减少邻树融合、同树拆分和树冠错分？

最终目标不是预设提升多少 F1，而是：在**独立测试集、完全相同的协议和训练预算**下，证明某些模块显著改善检测 F1、Coverage/实例 IoU 或复杂树冠分配质量，并报告计算开销。若模块无益，应明确报告负结果并回退。

拟定题目：**面向复杂森林点云的几何一致性与可靠性感知单木实例分割方法研究**。具体创新表述须根据最终消融实证和相关工作查新调整，不能将待验证假设写成既有成果。

## 2. 数据准备与严格划分

### 2.1 数据标签契约

参照 tree_learn/dataset/dataset.py 与 util/data_preparation.py：

- 原始实例标签 **-1**：未标注/忽略点；**0**：非树；**正整数**：单木实例 ID。具体 LAS/LAZ 的 treeID/classification 应先按项目加载函数核验。
- PyTorch 数据集内部的语义类别：**0=树，1=非树**。只对 mask_sem 有效点监督语义，只对 mask_off 有效树点监督 Offset。训练中的实例 ID 在不同 crop 间可重复，构造实例损失必须使用 **(batch_id, instance_id)** 联合键。
- 区分原始点、0.1m 降采样点和 crop 内点；禁止“同一个数字 ID 在不同森林表示相同树木”的错误假设。
- Wytham/LAUTx 的未标注点、林下植被、小树标注规则可能不一致；验证集与测试集不得根据模型预测重新人工修改 GT。

### 2.2 数据用途与方案的两层基线

**A. 执行基线 C0（必做，当前代码默认数据生产与训练协议）：**

- 训练来源：仓库 downloader 的 automatically_segmented_data：18 片 Lidar360 自动标注森林（A1N、A1W、G1N、G1W、G2N、G2W、G3N、G3W、G4N、G4W、L1N、L2N、L2W、LG1、LG2、LG3、O1N、O1W），不包含 L1W。
- 原始数据放在 data/train/forests/；按 **当前** configs/data_gen/gen_train_data.yaml 生成 **25,000** 个随机 35m crop（不是论文原来的 20,000）。
- 训练采用 **当前** configs/training/train.yaml 默认：1000 epochs，每轮 500 样本、batch 2；AdamW lr 0.003 / wd 0.001；余弦调度、warmup_t=50 epochs、fp16=True；初始化 hais_ckpt_spconv2.pth。
- 验证：使用独立的 NIBIO plot 16 若获取并核实；代码本身只指向 data/val/tiles/npz，**不会自动生成指定 NIBIO 的划分**，需手动准备。若暂缺 NIBIO 16，必须采用其他明确标识的临时验证区并将结果标为非论文同划分。

**B. 手工标注微调研究基线 C1（推荐，必须单独声明为“code-based mid 数据组合”）：**

- 从 **同一 C0 noisy 检查点**初始化；训练数据使用 FOR-instance train + FOR-instance val/test + LAUTx（论文 mid 数据组合）；**不使用 Wytham、不使用 L1W**。NIBIO plot 16 留为验证。
- main **没有自动化 mid 阶段脚本**，因此为它建立专用 YAML，所有研究方法复用完全相同的数据与训练预算。
- 为控制单卡成本，建议微调采用论文的 **12,500 optimizer steps**、batch=2、初始 lr=0.0005、无 warm-up、最小 lr=0.00005；以当前代码每轮 500 样本折算约 50 epochs。**这里是“对当前实现的明示实验配置”，不是 main 的默认微调行为，也不是逐位复现论文**。
- 如必须坚持“全部采用 main 默认 1000 epochs”，允许另建 C1-full 作为补充，但所有改进与对照都必须使用相同 1000 epochs，不能把 C1-short 与 E1-full 直接比较。

**C. 已发布权重的角色（工程回归测试，不冒充独立数据集成绩）：**

- model_weights_20241213.pth 和 model_weights_with_small_20241213.pth 可验证流水线是否能跑通与小树检测行为；官方 docs/segmentation_pipeline.md **明确警告发布的检查点可能在 L1W 上训练过**。使用这些权重在 L1W 上取得的 F1 不能视为独立测试结果。
- 官方论文中的 noisy/small/mid/large 与“现有发布 checkpoint 文件名”并非一一对应；每份权重须核对具体训练数据及来源。

**D. 测试集（固定，一次性最终验证）：**

- **L1W：**在确认当前实验训练集和初始化权重都未用过 L1W 后作为独立测试；否则仅标“非独立工程测评”。
- **Wytham Woods：**独立跨数据集测试；不参与训练、验证调参、阈值寻找及最佳模型选择。
- FOR-instance val/test **若已纳入 C1 训练**，绝对不能再作为 C1 独立测试。
- 需要额外数据选择时，新增“空间互不重叠的森林 plot 或区域”，确保统计独立性，不按随机点划分同一棵树的点。

## 3. 冻结的网络、训练与推理流程

### 3.1 网络与监督（main 实际执行）

**模型：** tree_learn/model/tree_learn.py 的 voxelize -> spconv input_conv -> UBlock(7层级) -> output_layer -> pointwise remap -> semantic_linear(2维) + offset_linear(3维)。默认不使用预计算 feats 值作为网络输入，但输入体素坐标仍编码几何位置。现有代码额外输出 backbone_feats（点特征）供推理阶段保存。

**训练数据流：** data/gen_train_data.py 按 35m 随机 crop -> TreeDataset.transform_train 增强（jitter/flip/rot/scaled/point_jitter）-> TreeDataset.getOffset() 按**代码中的低位 0.5m 点集均值**生成偏移标签 -> mask_inner/mask_sem/mask_off -> 网络 -> 两项损失。

**损失：**
L_base = 50 * CE(semantic_logits[masks_sem], semantic_labels[masks_sem])
       + mean_{i in masks_off}( ||offset_pred_i - offset_gt_i||_2 )

**训练：** tools/training/train.py；默认 1000 epochs，500 examples/epoch，batch=2，fp16=True，AdamW lr=0.003，wd=0.001，梯度裁剪配置为 True；每 20 epochs 验证与保存。当前 validate() 输出 semantic accuracy 与 offset MAE，**没有原生计算每轮实例 F1**。选择最佳权重须基于验证集 Offset MAE，且提供独立选择脚本/检查记录；不能用 Wytham 测试分数挑模型。

### 3.2 分割数据流（必须严格固定）

原始森林 -> 中心化以控制高绝对坐标 -> 0.1m 体素化 -> 0.6m 邻域计算 verticality -> 35m tile / 中央 8m / 4m 移动 -> U-Net 分别预测每个 tile -> 仅保留 masks_inner -> 按 0.01m 坐标舍入及分组均值融合 semantic logits、Offset（以及 features）-> global XY 上 Offset-shifted seed 筛选与 HDBSCAN -> 在 offset 后的 3D 坐标以 K=5 近邻给剩余预测树点分配实例 -> 标签传播到指定分辨率/原始点 -> 评测。

**聚类固定设置：**

~~~yaml
# configs/_modular/grouping.yaml（当前 main）
grouping:
  tree_conf_thresh: 0.5
  tau_vert: 0.6
  tau_off: 4
  tau_group: 0.15
  tau_min: 50
  use_hdbscan: True
~~~

注意：HDBSCAN 使用 min_cluster_size=50，并在满足 tree_prob/verticality/vertical-offset 的点的**偏移后 XY**坐标运行；tau_group=0.15 在 HDBSCAN 模式不参与计算。剩余点分配 uses K=5；默认 save_cfg.return_type='original'、save_pointwise=True、save_treewise=True。

在 P0 中必须保存 pointwise_results.npz 内的 coords、semantic_prediction_logits、offset_predictions、backbone_feats、input_feats、instance_preds_after_initial_clustering、instance_preds；未来只替换 P3/P4 时可直接复用相同逐点预测，避免重复训练和前向推理。

### 3.3 原生评价定义

执行 tools/evaluation/evaluate.py 与 tree_learn/util/eval.py：

- 在 GT 坐标上用 5-NN 将预测标签传播至评测点（注意这里也是 K=5，但**与推理阶段剩余点分配 K=5 是不同函数/用途**）。
- 对真实树与预测树建立 IoU 矩阵，Hungarian 一对一匹配，只有 IoU **严格 > 0.5** 才计入匹配。
- **检测 F1** 基于 Completeness/Omission、经过作者特殊规则过滤的 Commission，非简单“预测簇数精确率”。无标注小树对应的未匹配预测可能被排除，因此不可与其他评测协议直接拼表。
- **Coverage（最主要的实例分割指标）**：每棵真实树匹配预测最大 IoU，再对所有 GT 树平均；实例级 Precision/Recall 同理。
- 可额外统计 GT 树高分桶、小树漏检、相邻树合并、单树拆分、树冠顶部与外围错误、计算时长/CPU RAM/VRAM；但不得替代论文原生 F1/Coverage 主指标。
- 论文 Table 3 可作参考值，但**当前代码的基部、HDBSCAN/KNN 与训练预算不同，数值不能要求复现一致**。

## 4. P0：实验基础与诊断（在修改模型之前）

### P0-0 数据与执行审计

任务：依赖版本记录、数据 manifest、独立划分检查、C0/C1 配置冻结；保证原始 main checkpoint 和结果只读。先用一个 tile 做 GPU 前/反向及输出 shape 测试，然后小 plot 全链路、最后整片林地。

风险点与处理规约：

1. **AMP 梯度裁剪风险：**现有 train.py 在 scaler.scale(loss).backward() 后直接 clip_grad_norm_，未先 scaler.unscale_(optimizer)；也没有显式 clip max_norm，布尔 True 等价 1。先作为代码基线保留并记录。若修复，派生“B0-fixed”并在**所有对照与改进方法**中统一修复，不能只给改进组修复。
2. **学习率调度：**当前每个 batch 调用 scheduler.step(epoch)，按 epoch 而非真实 optimizer step；保留代码行为，记录实际学习率曲线；不声称与论文的 iteration scheduler 完全一致。
3. **基部标签细节：**getOffset 中 np.partition(z,10)[3] 不是排序后固定的第 4 小值。先测试边界/异常稀疏点；若修复则统一开启并单列基础设施对照。
4. **跨 tile 融合：**ensemble 以保留 2 位坐标的 DataFrame groupby 求均值，尤其 instance_labels/offset_labels 在重叠坐标上的聚合与类型转换需核实；冻结原代码并记录重复率。没有证据不得随意重写融合。
5. **空簇与异常：**没有有效 HDBSCAN 簇、少于 K=5 的参考点、坐标维度收缩时，现有流程可能无法完整运行；先用单元测试暴露，必要防御修改放入明确的工程修复对照并保持所有模型一致。
6. **数据体积：**25,000 个 crop 可能占大量磁盘（官方文档提及同量级可能约 700 GB）；必须先统计磁盘容量、内存峰值，再全量生成。

### P0-1 建立误差归因诊断

必须把“网络预测”“初始种子聚类”“剩余点分配”分开评价：
- 网络：树木语义点精度/召回、Offset L2/方向误差，按真实树高/偏移长度/距树冠边缘统计。
- 偏移簇：每个真实树偏移终点在 XY 的散布（如 RMS 半径）、与最近邻树终点间距、交叉重叠度。
- 初始 HDBSCAN：种子覆盖的真树比例、每个 GT 对应簇数、簇对应多个 GT 的比例、种子纯度、小树有效种子数。
- 最终 KNN：哪些点在聚类时未分配、KNN 前后真实树点归属的变化、在冠幅外圈/高处/近邻树冠的错误分配。

**仅诊断上界（禁止作为可部署模型结果）：**
- D1：以 GT Offset 替换预测 Offset，固定真实推理的后处理，确定 Offset 的潜在瓶颈。
- D2：用 GT 真实偏移误差选种子，仅看种子选择可提高多少性能。
- D3：固定已有初始簇，仅看最近邻归属的错误占比。
上述试验只可在有标注且用于研究诊断的数据上完成，不能在 Wytham 终测中靠标签选阈值。

**P0 出口：**明确主要瓶颈是“Offset 本身”“种子发现”“冠层归属”中的哪一类，完成可重复 B0/C1 基线报告。若没有明显偏移失真，后续可直接跳过 P1；若 KNN 已足够好，可跳过 P4。

## 5. 创新候选 I：几何一致性与实例分离感知的 Offset 学习（P1）

### 5.1 科学动机

现有 Offset Loss 是逐点回归，虽然 GT 目标本来指向同一树基部，但**没有显式约束不同树之间的间隔可辨性**。在相邻树干很近、树冠交错且标注带噪时，平均 L2 降低不一定带来聚类可分性提高。不能仅增加一个同树聚拢项就断言有效，因为该项与原始 GT Offset 监督高度相关。

### 5.2 具体方法（先做轻量约束，不改 U-Net）

记点坐标 p_i、预测偏移 o_i、监督偏移 o_i*、预测终点 b_i=p_i+o_i。针对每个有效训练实例 (batch_id, instance_id)=k 的中心 μ_k：

1. **方向约束（Direction）：**
   L_dir = mean_{i∈valid, ||o_i*||>ε} [1 - cosine(o_i, o_i*)]。
   对低幅度 GT Offset 禁用方向项以免不稳定；ε 为预先确定且只在训练验证集上调整的常量。
2. **实例内部紧凑约束（Compactness）：**
   L_cmp = (1/K) Σ_k [ mean_{i∈S_k} ρ(||b_i-μ_k||_2 / (r_k+ε)) ]。
   每棵树均衡贡献，采用 SmoothL1/Huber ρ 防止超大树影响损失；r_k 可用 GT 同树空间尺度预先计算并仅在训练中使用。
3. **可选相邻实例分离约束（Local Separation）：**
   仅在同一 crop 内基部足够接近的不同 GT 实例对上，约束预测终点中心保持可分距离：
   L_sep = mean_{(k,l)∈N} [max(0, m_{kl}-||μ_k-μ_l||_2)]^2。
   m_kl 应由 GT 基部间距或局部密度确定且有上界，避免把真实紧邻双干强行推远；此项只在 P1 前两项不充分且 P0 显示邻树合并是主要问题时单独开展消融。

总损失候选：L = L_base + λ_d L_dir + λ_c L_cmp (+ λ_s L_sep)。

**实现要求：**用现有 batch['coords']、batch['offset_labels']、batch['instance_labels']、batch['batch_ids']、batch['masks_off']；不得将不同 batch 中相同编号的树合并；以 index_add/scatter 线性聚合计算，不构造 O(N²) 点对矩阵；所有附加损失用 fp32 计算，检查零有效树实例、只有一棵树和裁剪不完整树的边界行为。

### 5.3 消融与否决条件

- P1-L0：C1 基线，原 Offset Loss。
- P1-L1：+ Direction。
- P1-L2：+ Compactness。
- P1-L3：+ Direction + Compactness。
- P1-L4：按需 + Local Separation，且单独报告增益。

其他条件均相同：同一 noisy checkpoint、同一 mid 训练 crop、同一随机种子集合、同一微调 step、同一 HDBSCAN+KNN、同一验证/终测协议。

**必要证据：**不只看训练 Offset MAE，要看实例分布的类内散布、最近邻树可分性、初始簇纯度、检测 F1 与 Coverage。若训练损失下降而检测/分割无一致收益，则标记为冗余损失，回退而非继续堆叠。

## 6. 创新候选 II：预测偏移不确定性与质量校准（P2）

### 6.1 核心创新

当前 pipeline 在聚类前依赖 P(tree)、verticality 和 abs(offset_z) 的**固定启发式规则**，不能区分“同样满足几何筛选但模型偏移实际上失真”的点。新增**点级偏移可靠性分支**，显式估计 Offset 的不确定性，而不是重复预测树木语义。

主干输出 f_i∈R^32 -> 2 层小 MLP -> s_i（对数误差尺度）-> q_i=exp(-clamp(s_i,s_min,s_max))（可靠性得分）。原 Offset Head 与 Semantic Head 都不删除，保证可用旧权重加载。

### 6.2 学习目标与训练防退化策略

基于预测误差 r_i = ||o_i-o_i*||_2，使用异方差回归目标（仅训练有效树点）：
L_unc = mean_i [exp(-s_i) * r_i + s_i]，其中 s_i 作区间裁剪或其他稳定约束。

这只是候选损失；要注意如果直接和 Offset 主损失联合优化，网络可能通过提高估计误差尺度来掩盖大残差。必须评测 Offset MAE、s_i 的分布、梯度范围，并设置：
- **P2-A：冻结已有主干与 Offset Head，仅训练可靠性 MLP**，使用 detach 的 r_i 作为监督或拟合 log(r_i+ε)，先评估预测信息是否存在；
- **P2-B：可选联合微调**，所有方法相同训练预算与权重来源，校验 L_unc 的量纲、损失权重和稳定性；
- 置信度不能从 GT 在推理时重算；GT 只作为训练损失/离线诊断。

### 6.3 评测可靠性的“真值”

- 误差风险识别：真实 Offset 残差的分组均值、Pearson/Spearman 相关性、误差排名前百分位捕获率。
- 校准：按 q_i 分桶，比较各桶的平均 r_i 与预测误差尺度；固定可靠性分桶规则。
- 下游关联：按 q_i 分桶统计种子纯度、不同树的误合并、小树召回与 Coverage。
- 同时报告可靠性头新增的参数量、显存及推理延迟。**可靠性相关性很弱时直接否决 P2/P3 路线。**

## 7. 创新候选 III：可靠种子驱动的 HDBSCAN 与保底召回（P3）

### 7.1 研究假设

即使大部分树干候选有较高 verticality，少量错误 Offset 点仍可能桥接相邻树簇。若先用高可靠种子建立高纯度实例，再对剩余点扩展，有望降低假合并；但阈值过严可能漏掉低密度小树。因此必须同时设计**纯度与召回平衡**，不是简单“删掉不可靠点”。

### 7.2 方法设计

保留原始的 candidate mask：
M0_i = [P(tree)≥0.5] ∧ [verticality_i>0.6] ∧ [abs(offset_z_i)<4]。

在 M0 内结合 P2 输出 q_i 构造可靠性评分，首版不引入新的训练参数，只用已校准的 q_i 作为种子优先级：

- **方案 S1（纯后处理）：**在 M0 内按 q_i 选择核心种子，仍以 **XY 偏移坐标 + sklearn HDBSCAN min_cluster_size=50** 获取主簇。
- **方案 S2（防漏兜底）：**对第一遍未分配的候选点执行空间约束的第二阶段补簇；仅当达到原始 50 点规模、语义与几何一致性条件时允许建立新的实例。已可靠归属的点不参与第二轮重定义。
- **方案 S3（可选）：**在局部空间网格进行种子分位数筛选，避免大树候选挤占全部核心种子；网格划分与阈值必须在验证集锁定。

所有方案都保留“非树=0、未归属=-1”的标签语义。加入“没有有效初始簇”“小于 5 个参考点”等特殊输入的明确行为，优先作为统一防御性修复，而不把工程错误恢复算作科研增益。

**严格隔离对照：**E3=原网络输出+原 HDBSCAN；E4=同一网络输出+置信度种子；E5=再加二次补簇。调种子规则只用验证集，不用 Wytham 测试 F1 回调。

### 7.3 主要指标

新增种子覆盖率（每 GT 是否至少有一个高纯度正确种子簇）、种子纯度、簇合并/拆分、小树召回、候选点保留率；最终以 F1/Coverage 及相同点密度协议的运行耗时为准。对于稀疏小树，任何严重漏检都必须单独报告，即使整体 Precision 上升。

## 8. 创新候选 IV：实例原型与几何联合树冠归属（P4，可选）

### 8.1 为何针对当前 KNN

当前 assign_remaining_points_nearest_neighbor() 以偏移后的 3D 坐标，在初始聚类标注点上执行 KNeighborsClassifier(n_neighbors=5)。远离树干且与邻树树冠交叠的点，可能更接近错误实例簇。主干已有 32 维 backbone_feats，但当前 KNN **并未使用**。

### 8.2 轻量原型分配

对每个已识别实例的可靠种子点集合 S_k，构造一个置信度加权的 32 维特征原型：
z_k = (Σ_{j∈S_k} q_j f_j) / (Σ_{j∈S_k} q_j + ε)。

对未分配点 i，仅在偏移位置附近取 **Top-M 个候选实例**（M 初始可尝试 3/5；避免所有点×所有实例的全连接）。候选打分组合：
- d_shift(i,k)：偏移后坐标到实例中心的距离；
- cos(f_i,z_k)：点特征与种子特征原型的相似度；
- d_raw(i,k)：原始点位置与该树种子/局部树干几何的相容性；
- q_i：偏移可靠性；
- 可选邻域一致性：近邻点已分配实例的支持程度。

score(i,k) = -α * normalized_d_shift + β * cosine(f_i,z_k) - γ * normalized_d_raw + δ * local_support。
首轮采用固定权重验证可解释性；若有明显增益，再引入小 MLP 学习 score，训练候选实例分类交叉熵。模型只允许从**训练 crop 的预测种子**和相应 GT 建立监督，不能用测试 GT 构建原型。困难负样本采用同一局部场景的相邻树木，而非随机无关树木。

保底策略：若局部没有可靠候选或评分不稳定，使用现有 K=5 分配；不无故将前景树点改成背景。保存 E6（仅几何）、E7（几何+特征）、E8（学习评分）三组结果。

### 8.3 资源与边界

全场景 N 点 × 32 维特征容易造成 CPU 内存压力，应利用已经生成的 pointwise_results.npz，并按空间区块/实例候选分批处理；不能在 GPU 上构建 N×K 全局矩阵。记录额外磁盘、CPU RAM 峰值和运行时间。若 P0 证明 KNN 已不是主要瓶颈，应跳过 P4。
