## 1. 研究问题与两个改进方向

**方向一：几何一致性 Offset 学习。** 原始网络逐点回归到树基部的 Offset，但点级回归误差降低不一定让同树偏移终点在聚类空间中更紧凑。候选方法为方向损失和同实例预测终点一致性损失，重点验证是否减少邻树合并和单树拆分。数学定义与避免伪创新的必要对照见附录 B。

**方向二：Offset 可靠性感知实例聚类。** 原始流程通过语义概率、垂直性及 Offset Z 筛种子，对偏移后的 XY 做 HDBSCAN，再由 5-NN 分配剩余点。给现有主干特征加小型可靠性头，学习 XY Offset 残差尺度，在**原始几何候选点集合内部**优先选择更可靠的种子。实施细节与公平筛点对照见附录 C。

只有实际错误分析证明 5-NN 冠层归属是明显瓶颈，才考虑实例原型等第三个方向；**当前不作为必做任务**。

## A. 网络、监督与实现对照

**当前网络入口：**[tree_learn/model/tree_learn.py](../../tree_learn/model/tree_learn.py)，七层级稀疏卷积 U-Net，输出 semantic logits（2 类）与 Offset（3D）；网络默认输入开关见 [configs/_modular/model.yaml](../../configs/_modular/model.yaml)。

**当前训练监督：**[tree_learn/dataset/dataset.py](../../tree_learn/dataset/dataset.py) 的 `TreeDataset.getOffset` 计算树基部的监督 Offset。实例标签按 `(batch_index, instance_id)` 组合，不能合并不同 Crop 中恰巧编号相同的树；忽略点不参与有效监督。

记 `p_i` 为点坐标、`o_i` 为预测 Offset、`o_i^*` 为按当前代码规则得到的真实 Offset，`b_i=p_i+o_i` 为预测偏移终点；原损失：

```text
L_base = 50 * CE(semantic_prediction_logits, semantic_labels, masks_sem)
       + mean_{valid tree points} ||o_i - o_i*||_2
```

**当前推理与评价相关源码：**[tree_learn/util/pipeline.py](../../tree_learn/util/pipeline.py)、[tools/pipeline/pipeline.py](../../tools/pipeline/pipeline.py)、[tools/evaluation/evaluate.py](../../tools/evaluation/evaluate.py)。当前 `configs/_modular/grouping.yaml` 中 `tau_group=0.15`，但**默认 HDBSCAN=True 时不代表它按 0.15m 半径聚类**。

## B. 创新点一的候选数学实现

以下为几何一致性改进模型的候选数学实现。只有进入相关实验时才需查阅，不要求为开工先完成全部消融。

**方向项**（跳过 GT Offset 近零点，避免方向不确定）：

`L_dir = mean_i [ 1 - cosine(o_i, o_i*) ], for ||o_i*|| > eps`

**先纠正一个重要的数学等价：**设当前 Crop 内树 k 的真实监督基部为 `g_k`，每个有效点满足 `o_i^*=g_k-p_i`。于是：

```text
||(p_i + o_i) - g_k||_2 = ||o_i - o_i*||_2
```

因此，**直接把预测终点约束到 GT 基部的所谓 Compactness Loss，本质上仍是 Offset 回归**；即使用 Huber、按树均衡或除以实例尺度，也只能称为**实例均衡的稳健 Offset 回归基线**，不能独立包装成新增的实例结构信息。

**新增的候选实例一致性项**：在训练 Crop 内，对每个有效实例 k 的监督点集 `S_k` 定义预测终点 `b_i=p_i+o_i`、**预测终点均值** `b_bar_k = mean_{i∈S_k}(b_i)`，然后计算：

```text
L_cons = mean_{k∈valid instances}
             [ mean_{i∈S_k} ||b_i - b_bar_k||_2^2 ]
L_E1 = L_base + lambda_dir * L_dir + lambda_cons * L_cons
```

`b_bar_k` 必须由**当前预测**计算，不能换成 GT 基部。首版保持**不使用 `detach`**，以直接对应上面的数学定义，并便于后续扩展。**严格限定在“同实例等权平均 + 平方 L2 离差”这一形式时，均值是否 `detach` 的一阶梯度实际上相同**：

```text
L_k = (1/n_k) Σ_i ||b_i - b_bar_k||²
∂L_k/∂b_i = (2/n_k) · (b_i - b_bar_k)
Σ_i (b_i - b_bar_k) = 0
```

不应再以“`detach` 会改变本式一阶梯度”为理由要求不 `detach`。**若改成 Huber、非均匀权重、非算术均值中心或其他形式，梯度等价性需重新推导**。原有 `L_base` 仍负责锚定 GT 基部，否则 `L_cons` 单独使用会容忍整个实例的共同平移。

**公平对照必需：**对同一 `S_k` 实现 `L_huber_inst = mean_k mean_{i∈S_k} Huber(||o_i-o_i*||)`，按实例均衡并可单独加入原损失。即使 `L_cons` 在形式上不等价于 GT Offset Huber，也仍与逐点回归有统计关联；特别在平方误差下，围绕 GT 的误差平方可以分解为实例均值误差和实例内部方差，因此**不能仅凭新公式宣称理论独立性或论文创新性**。只有对比 `L_base`、Direction-only、`L_huber_inst`、Consistency-only、组合方法，并观察 HDBSCAN 簇纯度、合并/拆分率和 Coverage，才能判断是否有可归因增益。

**实现边界：**实例键用 `(batch_index, instance_id)`，忽略 -1/0，按同树有效点计算；对空树、过少点的实例安全跳过；实例均衡；计算 `L_cons` 时用 fp32。尺度归一化、最小实例点数和 `lambda_dir/lambda_cons` 在 E1 开始前锁定，仅用训练/验证数据调整。Local Separation 仍仅在错误诊断支持时作为独立可选消融。

## C. 创新点二的候选实现与简单对照

**可靠性头：**`f_i`（当前 32 维 backbone point feature）经小 MLP 输出预测 XY Offset 残差尺度 `s_i`：

```text
r_i_xy = ||(o_i - o_i*)[:2]||_2
L_quality = mean_i [ exp(-s_i) * r_i_xy + s_i ]       # 数值稳定需 clamp 或其他约束
q_i = exp(-clamp(s_i))                                # 仅是相对可靠性分数，不是概率
```

首版 E2 在**同样的 mid 训练预算**内训练网络和新头；质量预测目标的梯度使用方式（是否 detach Offset 残差、头与主干如何联合优化）应在 E2 代码实现前固定并配套简单对照。关键是先检查**原始 HDBSCAN 候选种子 M0 内**的 `q_i` 与真实 XY 残差及错误种子概率是否相关，而不是只报全体点的 XYZ 相关性。

**聚类不变的主体：**仍在满足 `P(tree)≥0.5 & verticality>0.6 & |offset_z|<4` 的点中选种子，对偏移后的 XY 使用 HDBSCAN(min_cluster_size=50)，随后按原代码在偏移后的 3D 空间为剩余树点做 5-NN。E2 改动在于可靠性的**种子筛选**及必要的漏检补偿。

**必需的最低公平对照（不重新运行网络）：**先固定一个 E2 checkpoint，完成一次 Tile 前向预测与跨 Tile 融合，保存**同一份**坐标、semantic logits、Offset、特征和可靠性得分。对同一候选集 M0，分别用①原始 M0 全量，②固定随机种子、按比例 R 采样，③按语义置信度取前 R，④按学习可靠性取前 R；②③④必须保留**相同数量**候选点。其余 HDBSCAN/K=5 不变，复用相同预测缓存计算 F1/Coverage/小树覆盖率。若只删点就能获得同等收益，应如实否决可靠性筛选的独特贡献。**另将 E2+原始筛点与 E0+原始筛点比较**，区分可靠性头训练对网络预测本身的影响和筛点策略的影响。

**跨 tile 处理：**主干点特征和质量头预测须遵循现有 tile 内预测、坐标融合，再进行全局种子选择的流程；不能让同一个实际点的不同 tile 预测未经聚合直接参与全局 HDBSCAN。

## D. 必要的训练和运行检查（按需使用，不作为独立项目）

- **初始化与续训不同：**从公共权重开始新实验时，只继承模型参数并重新创建 optimizer/scheduler/GradScaler；新可靠性头允许明确列出的缺失参数。中断后继续同一任务才恢复完整状态和 epoch。
- **AMP 梯度裁剪：**正确顺序为 `scaler.scale(loss).backward()` → `scaler.unscale_(optimizer)` → `clip_grad_norm_` → `scaler.step(optimizer)`。统一修复应对基线与创新组同时生效；如验证异常，先用已有 checkpoint 做有针对性的对照，不直接归因。
- **Checkpoint：**记录训练配置、代码 SHA、训练轮次/成功更新数和验证选模记录；验证轮完成后再保存。恢复需核对 optimizer、LR scheduler、GradScaler 和必要的随机状态。
- **微调学习率：**新 50-epoch 训练不能沿用自动标注训练阶段的 1000-epoch 调度器；检查实际学习率曲线和最后一次验证。
- **异常验证 Offset：**只有影响权重选择与复现时才排查；优先复验权重与固定验证 Tile，必要时检查 BatchNorm 统计、逐 Tile 错误和版本差异。
- **结果来源：**整林推理缓存里的 GT 可能只是占位值；做正式实例评价要用原始 GT 并正确坐标对齐。

## E. 每次实验最少记录

每组实验只需保存：实际使用的配置及代码版本、公共初始化权重、数据清单、最终或最优 checkpoint、预测/评价产物、一次清晰的结论。建议表头：

`模型 | 权重来源 | 训练预算 | NIBIO 验证 | L1W F1/Coverage | Wytham F1/Coverage | 失败案例 | 运行成本`

额外消融只为明确的归因问题服务。不要为初期探索先创建十几套训练方案、重复生成已合格数据或重复审计不变的数据集。
