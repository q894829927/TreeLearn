# 根据真实数据判断 ForestABC 后续方向

日期：2026-10-20。数据路径：`E:\新建文件夹\data\data\data`。

本次只做数据读取、标注计数、几何诊断及代码分析，没有导入或执行模型，没有运行训练、模型推理或模型单元测试。完整扫描 18 个自动标注森林、L1W 的评价版和 Wytham，共 20 个 LAZ 文件、约 13.82 亿点。原始数据未修改。LAZ 读取工具安装在被 Git 忽略的独立临时目录中。

主要统计见 [聚合 JSON](assets/forest_abc_dataset_audit_20261020.json)。RGB 另在 5 份文件中各抽查 32 万点。几何诊断另取 5 个森林各 3 个半径 16 m 的内部块，属于有限样本分析。

## 1. 数据显示的主要差异

下表的竖向跨度为每个标注实例的 `max(z)-min(z)`，不等于经过地面归一化的林业树高；它用于比较当前标注实例的几何尺度。

| 数据 | 实例数 | 实例竖向跨度中位数 | 跨度小于 9 m | 未标注点比例 |
| --- | ---: | ---: | ---: | ---: |
| 当前训练的 13 个自动标注森林 | 4,883 | 30.07 m | 0 | 0% |
| 当前验证的 5 个自动标注森林 | 1,782 | 32.72 m | 0 | 0% |
| L1W 人工评价版 | 156 | 33.06 m | 0 | 40.83% |
| Wytham | 877 | 14.69 m | 214，24.40% | 53.54% |

训练实例中仅 57/4883（1.17%）跨度低于 10 m，且这些也都不低于 9 m；Wytham 有 269/877（30.67%）低于 10 m，58 棵低于 5 m。两者 XY 最大跨度的中位数也分别为 9.72 m 和 6.10 m。

这支持两个分别处理的判断：

- Wytham 的小尺度实例明显缺少对应训练样本，当前仅 0.9～1.1 倍的缩放增强覆盖不足。仅把主干/注意力做得更复杂，不会自动补上这部分监督。
- 当前源域验证的尺度与源域训练较接近，因此源域 F1 低 4.48 个百分点不能主要归因于上述小树差异。源域需优先检查训练条件、query 覆盖、掩码学习和后处理损失。

这些是自动算法分割得到的训练标签，而非逐树人工金标准；官方数据页也明确把 18 个文件列为 automatically segmented MLS scans。不能把大量点数直接等同于大量独立高质量实例。[官方数据说明](https://data.goettingen-research-online.de/dataset.xhtml?persistentId=doi:10.25625/VPMPID)

## 2. 原版权重与新模型的训练条件没有对齐

本地 `model_weights_with_small_20241213.pth` 的大小为 120,627,653 字节，MD5 为 `38266e515dc387ac5ca32619e791cc20`，与官方 Dataverse 元数据完全一致。当前缓存生成模板也指向此文件名；服务器缓存实际使用的权重仍可用 cache.json 中的来源记录进一步核对。

官方 ReadMe 描述的权重链条为：自动标注数据训练 → L1W 人工数据微调 → 多个来源的人工标注/修正数据微调 → 更新点云过滤配方 → 训练小树版本。它不是只用当前 13 个自动标注森林从随机初始化训练的模型。[官方权重说明](https://data.goettingen-research-online.de/api/access/datafile/118510)

G4N/G4W/L1N/O1N/O1W 属于原始 18 个自动训练文件。按官方公开训练说明，这些文件属于官方权重训练来源，而对当前 ABC 是留出的验证森林。当前比较仍能回答“是否超过现成官方模型”，但同时混合了训练数据、初始化、训练配方和架构的差别，不能把差距全部归因于 A/B/C 模块。

官方管线也明确说明 L1W 参与过所提供 checkpoint 的训练，因此官方权重在 L1W 上的结果不能直接称为未见场景测试。[官方管线说明](https://github.com/ecker-lab/TreeLearn/blob/main/docs/segmentation_pipeline.md)

ReadMe 所列人工微调资料包含 Calders 等人的数据；对应论文涉及 Wytham Woods。现有信息不足以证明本地这一份 Wytham 的具体扫描/区域与训练数据重合，也不足以把官方权重的 Wytham 结果保证为严格未见；需核对具体训练清单。[该数据来源论文](https://www.mdpi.com/2072-4292/10/6/933)

**这个训练条件差异，是之前设计组合和估计效果时没有充分对齐的地方，应修正预期。** 当前 5000 步 F1=83.72%、Coverage=73.97% 仍然没有超过基线；这项数据分析不改变实测结论。

## 3. 抽样确实较重，但没有证据证明它是全部原因

15 个内部块先用坐标独立生成近似 0.1 m 代表点，再模拟 0.2 m 输入体素和抽样。这里没有执行服务器的精确滤波/体素相位，也没有任何网络。

| 几何表示 | 保留体素比例中位数 | 局部 GT 几何 oracle 平均最佳 IoU |
| --- | ---: | ---: |
| 0.2 m 全量 | 100% | 99.37% |
| 0.2 m，均匀抽 65,536 | 17.31% | 97.43% |
| 0.2 m，空间保留后补齐 65,536 | 17.31% | 97.54% |
| 0.2 m，均匀抽 131,072 | 34.62% | 98.34% |
| 0.1 m，均匀抽 131,072 | 13.33% | 98.18% |

解释：使用 GT 为每个目标树独立选择最有利的代表点单元集合，计算该树在当前裁剪块内的最佳二值掩码 IoU；未知点忽略，评价局部至少有 20 个标注点的树。它不考虑模型能力、query 选择、整树裁剪、互斥分配或 NMS，**不是模型结果，不是整林 Coverage/F1，也不能作为承诺的性能上限**。

局部 65,536 体素的保留率约为 14.2%～22.5%，说明密集区域的信息损失值得处理；但在这个乐观几何诊断中，大多数树仍可达到 IoU>0.5。因此不能仅凭降采样就解释当前全部漏检，也不能据此推算增大预算能让 F1 涨多少。

固定预算下，直接把体素改为 0.1 m 不保证更好：候选体素也更多，会被进一步抽掉。空间采样在这批样本上的 oracle 改善也有限，不能仅凭名字认为它必然解决问题。

部分块存在“core 内有该 GT 的点，但没有属于该 GT 的多数标注代表锚点”的现象。这个统计包含只在 core 露出很少枝尖的树，且其他块可能检出它，不能解释为整林漏检。它提示下一步应量实际 query 的逐树覆盖，不能只看正 query 总数。

局部可见 GT 数为 16～62 棵，而当前最多 300 个 query。没有证据表明应先扩大 query 总数；更需要确认它们是否重复覆盖少数大树。

## 4. 下一步的优先级

### 第一优先：先把源域漏检定位到具体环节

对同一个 checkpoint，在服务器生成一次诊断账本，逐 GT 记录：

1. 有没有输入代表、有没有通过语义候选筛选、最终有没有 query 覆盖。
2. 最好的原始提案 IoU 是否超过 0.5。
3. 是否在质量阈值、局部 NMS、全局 NMS 或点分配阶段损失。

GT 只用于预测后的审计，不作为预测输入。先区分“没产生可用掩码”和“可用掩码被后处理丢弃”，再选改法。现有 summary 只能证明最后结果退步，还不能判定 GeoMixer/MFA 哪个模块无效。

### 第二优先：对齐训练课程，加入按树均衡和小尺度训练

- 选可核对来源、结构兼容的主干预训练，随后联合训练主干和 decoder。与官方比较时记录初始化与数据；官方权重见过的场景不宣称为独立泛化测试。
- 块采样增加“先等概率抽树、再抽该树附近的块”；mask loss 增加“同一 GT 的多个 query 先平均，再对树平均”，减少大树/重复 query 主导监督。GT 引导采样只用于训练。
- 把较窄的 ±10% 缩放扩展为能覆盖目标尺度的候选增强，如约 0.5～1.2 倍，配合点密度/遮挡扰动；这只是候选配方，需要源域验证，并非已证实增益。
- 为 Wytham 类型的小树补充独立人工小树数据。L1W 评价版的 156 棵以高树为主，单靠它微调仍不能补足 <9 m 的尺度缺口。
- 如果目标允许使用目标域标注，可划定独立训练区做少量监督域适配，并留空间隔离的测试区，明确报告为域适配结果，不与当前零目标域训练的结果混用。

### 第三优先：增加有效细节，建立粗细两级掩码

- 先尝试增大体素预算，并采用可计算纳入概率的空间/高度分层采样。已有 5.5 GB 显存峰值提示可做预算检查，但不能据此保证翻倍后一定不 OOM。
- 抽样方式改变时同步调整损失权重。当前 `total_voxels / selected_count` 校正以均匀抽样为前提，不能直接套到非均匀采样上。
- 保留大范围粗体素上下文，增加原 0.1 m 点上的可训练细点掩码头，使用插值特征与相对坐标，推理按点分块。当前只把体素二值 mask 最近邻传播回细点，细节无法独立修正。

### 第四优先：将 MFA 改为完整 decoder 的残差增强

当前后 5 层 cross-attention 被 MFA 区域汇总代替。MFA 依赖上一层预测的 hard mask，早期空/错误区域可能限制后续修正。若诊断显示有 query 但原始 mask 质量不足，可优先恢复完整跨点注意力，让 MFA 作为较轻的残差增强；对粗上下文 token 做 cross-attention 控制成本。

这是一条基于代码结构的待验证假设，数据统计不能证明 MFA 就是失败原因。GeoMixer 也先保留为残差，不因最终 F1 一项结果就归因删模块。

## 5. 建议下一版完整组合

```text
有合适预训练的稀疏主干
  + 粗上下文 / 细点特征
  + 空间与高度分层的候选、embedding 或中心信息选 query
  + 保留标准 cross-attention 的森林 decoder
  + 细点 mask head
  + 小幅 GeoMixer / MFA 残差增强

训练：按树均衡 + 尺度/密度扰动 + 独立人工数据微调
审计：query 覆盖 -> 原始 mask -> 筛选/合并 -> 最终 GT 匹配
```

重点是先提高树的覆盖与实例掩码学习，再由完整源域和目标场景结果判断是否有效。当前实验可继续完成 10000 步验证，用趋势判断是否需要提前转入上述诊断；这份分析没有修改正在使用的模型、配置或阈值。

## 6. 可用特征与标注边界

20 份完整扫描中 intensity 均为零，增加强度通道没有新信息。5 份 RGB 抽查中，所有拥有至少 10 个抽样点的树 ID 均在各自树内保持固定 RGB，且样本中颜色数与实例数相同，强烈提示按实例展示着色，不能把它当作真实相机颜色加入模型。

更值得尝试的是不依赖 GT 的几何特征，如地面相对高度、垂直度、局部平面性/密度；地面估计须从输入点云计算，不能读取 classification/treeID 作为输入捷径。

Wytham 53.54% 和 L1W 40.83% 的未标注点必须保持 ignore。当前代码已经忽略负标签，不需要为此重写；新细点头、增强和微调也要保留这一约定。L1W 的不同分辨率、评价版及 pipeline 副本属于同一场景，不应当作独立新数据；部分版本还存在坐标平移，评价需正确对齐。
