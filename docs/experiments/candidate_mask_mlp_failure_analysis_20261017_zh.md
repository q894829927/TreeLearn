# A1 失败分析：证据、设计不一致与下一步信息需求

日期：2026-10-17。依据服务器回传的 pilot audit、源域完整评价/事后诊断、Wytham 固定权重评价，以及当前实现代码。本地只读取代码和已回传 JSON，没有运行点云、模型或测试。

2026-10-18 更新：[A1b 受控排序监督结果](candidate_mask_mlp_a1b_results_20261018_zh.md) 已回传。相对 A0，Coverage +0.561 pp，但 F1 -1.656 pp、Commission +3.359 pp；相对 A1 仅多 3 个 TP、多 45 个 FP。当前排序实现没有带来整体改善，下一步使用既有 CPU 诊断核算本轮 FP 转移和两类操作影响。下文的早期假设与“待验证”描述按当时证据保留，以本次结果更新为准。

## 1. 结论的层级

效果退化已经确认；部分退化方式有定量证据；尚未通过受控训练证明某一个机制是主因。因此不能仅把“竞争监督不一致”当成已经证实的根因，也不能从当前结果断言 MLP 容量不足、主干特征无效或 query-mask 路线不可行。

### 已有实验支持的信息

1. **候选和区域并非完全没有可改善的几何空间。** Pilot A1N 的 Coverage 为 77.076%，GT oracle 为 93.943%（+16.866 pp）；G4N 为 79.630% → 97.306%（+17.676 pp）。这只是两处 pilot 的理想上界，不是 Wytham 的上界，也不保证当前输入/监督能学到。Oracle 使用全体候选和全局一对一分配，当前训练却按候选独立选目标并筛选，二者并不等价。
2. **源域改善主要表现为点集清理，跨候选重分配尚未带来总体收益。** 源域仅丢弃点：Coverage +0.393 pp、F1 -0.794 pp；仅改归属并回填未分配点：Coverage -0.120 pp、F1 -0.570 pp；完整 A1：Coverage +0.308 pp、F1 -0.595 pp。这些是固定预测的事后干预，存在交互，不能相加解释为独立因果贡献。
3. **简单回填或禁止改归属不能救回当前源域版本。** 上述两个单独操作的 F1 都为负，因此不能只把所有失败归于未分配阈值，或仅取消竞争就认为问题已解决。
4. **候选减少并不等于误检减少。** 源域消失的 170 个候选中，164 个原本不计入 FP，只有 6 个原计数 FP；新增 FP 中 52 个从原不计入误检的未匹配候选转入，12 个从原已匹配候选转入。计数资格变化解释了部分 Commission 上升，但并未消除真实匹配损失。不能将这些比例直接套用到 Wytham。
5. **丢点有真实代价。** 源域 1,188,829 个未分配点中，705,127 个属于 GT 树（59.31%）。它们原来属于树并不证明原候选身份正确，但最终丢弃意味着未归入任何树，不能统称为去噪。
6. **当前收益未迁移到更困难的外部场景。** Wytham F1 -3.658 pp、Coverage -3.214 pp、Point precision -2.724 pp、Point recall -4.670 pp；丢失原匹配 GT 35 棵、恢复 4 棵。源域点精度提高/召回下降的模式在此变成两者同时下降，不能用单一“更保守但更干净”概括外部结果。
7. **已排除的是具体运行异常，不是所有实现问题。** 完整结果非空、所有原前景点均被评分，模型有明显过阈值概率。不能再按 smoke 的全部低于阈值或漏评分解释当前结果。训练/验证损失确实下降，也不能简单说模型完全没有学到东西。

## 2. 代码确认存在的训练/推理不一致

### 2.1 同一 GT 的多个候选都被教成正例，最终却强制独占

`evaluation.audit_forest` 对每个候选独立选择最大 IoU 的 GT，不强制不同候选对应不同 GT。`RegionDataset.__getitem__` 把区域内属于该 GT 的全部点标为正例；`model.mask_loss` 独立计算每候选 BCE/Dice，没有共享点上的竞争损失。

因此，若候选 A、B 都对应同一棵树，其重叠区域内一个树点可以同时获得 A=正、B=正的监督。独立损失允许它们同时高分；`inference.update_winners` 却必须给这个点选择唯一实例 ID，且没有后续同树候选去重/合并。这可能使同一棵树继续碎片化，或被细小分数差重新切分。

这是代码允许的机制，不是已统计到的 Wytham 成因。还需量化训练中重复 GT 目标的数量，以及丢失 GT 是否集中在多个候选竞争的区域。设计上的选择应明确：训练唯一代表，或允许多代表并在最终实例形成时解决重复；不能仅训练独立成员概率后默认 argmax 就会形成正确实例。

### 2.2 训练点集包含部署阶段不可分配的点

`data.prepare_regions` 保存区域内所有点，`stratified_sample` 按 GT 分组采样，没有 `baseline>0` 限制。`predict_forest` 则明确只评分 `baseline>0` 的点，原背景永久保持 0。

这意味着训练/验证损失会覆盖部署阶段被排除的点：若 GT 树点被原语义分支判成背景，它在训练中可以成为正例，但当前推理不允许恢复它。区域内大量 GT 背景也参与训练人口权重，而实际竞争集中在原前景点上。因此损失下降可能主要反映完整区域任务的改善，未必反映实际可执行的邻树归属改善。

该支持集不一致是明确事实；实际影响需要统计原背景中的训练正例占比，以及 loss 在原前景/背景上的分项。采样已有反采样权重，不能简单把问题归于 50%/25%/25% 的抽样比例。若保持固定语义前景，训练与验证也应首先明确是否限制到同一可部署支持集；若要恢复语义漏检，则应另立扩大任务范围的实验。

### 2.3 训练候选经过质量筛选，部署使用全部候选

训练只使用 `supervision.valid`：标注比例至少 0.8，含树候选还要求 IoU 至少 0.1、目标纯度至少 0.5；推理对所有候选评分。Pilot A1N：641 个候选中训练可用 453 个，其余 188 个；G4N：364 个中可用 295 个，其余 69 个。

筛选对保护未知标签是必要的，但也让部分困难候选缺少直接监督。未参与监督的候选在推理中仍有同等抢点机会。应分开分析“可充分标注但困难”的候选与“无法可靠标注”的候选，未知点继续忽略；不能直接把所有被筛掉的候选当负例加入训练。

### 2.4 优化和选模型依据的是局部损失，目标指标来自全局实例形成

`run.train` 按固定抽样的候选 BCE/Dice 选 best checkpoint；完整评价在所有候选竞争后做 IoU > 0.5 匹配。独立掩码的小幅变好可以伴随最终实例切分变坏，第 26 轮最低验证损失只证明它在当前代理指标上最优，并未证明它是全部 checkpoint 中 F1 最优的一轮。

未来应在源域的预定检查时点观察完整实例指标与局部 loss 的关系，再预先定义选模规则；不能在看到 Wytham 后扫描 epoch 或阈值选外部最优结果。

## 3. 结构和决策规则带来的风险

原候选 GT-free mean/max 特征、bbox 中心/尺度和投票中心都来自已有预测。误合并、离群点或邻树污染会同时影响候选描述和相对几何；均值/最大值不保留点集的空间布局。MLP 逐点判断，未显式观察候选之间的关系。当前结果尚未分别证明特征不足、描述污染或缺少上下文的影响，故这些属于次级假设，而不是优先直接增加 attention 的证据。

分配规则仅在**分数完全相等**时优先原 owner。原成员标记虽已作为输入，但没有保证只有具备可靠相对优势才更改归属；0.61 对 0.62 这样的分数差就足以触发改归属。已有强基线下，成功机制需要净修复错误而少破坏正确分割。下一轮可研究保留原归属的残差决策，但应作为单独变量，不能与损失、特征、阈值同时修改而失去归因。

固定原前景、固定候选 ID 的设计还决定了能力边界：原语义漏检无法恢复；完全没有可用候选的树无法新增实例；单个候选不能主动输出多个新 ID。这些限制缩小了上限，但不能用来解释为什么原已匹配 GT 又被损坏。

## 4. 下一步按信息价值排序

先复用已有缓存和保存预测做 CPU 诊断，不重新跑主干或训练：

1. Wytham 分离仅丢点、仅改归属两种操作，并逐候选对账新增 FP、丢失 GT 的 IoU 变化，判断源域机制是否也出现在外部。
2. 在源训练/验证缓存上统计：同一 GT 对应多个有效候选的比例；被筛掉候选的类型；GT 正例中原语义背景占比。对 Wytham 的标注情况作事后分层诊断，不用它重新选训练数据或调参。
3. 只有在这些结果支持后，预先定义单变量 A1b。优先对齐可部署点集，再分别检验竞争/重复候选监督和保护原归属的决策；保留原 MLP 作对照，避免一次把多个机制混入。原始 A1 失败结果保持有效。
