## 已获得的信息与证据边界

- 本轮不是空预测或质量分数全部低于阈值。每森林质量分数最大值约 0.94–0.95，正常产生了掩码与新实例；但这些范围不能证明分数已校准。
- 累计查询 356864 个，块内抑制后提案 22230 个，全林 NMS 留下 3077 个，互斥分配后仍有 3070 个实例。仅 7 个全林保留掩码完全无剩余点，当前汇总没有记录其他掩码被裁掉的比例，不能据此确定碎片贡献。
- 原背景区域恢复的 GT 树点合计 6438；最终未分配 GT 树点合计 1446186。这不是同一批点的成对迁移，但说明恢复能力尚未抵消未分配问题，不能只用支持新实例/背景点参与来声称收益。
- 最佳 checkpoint 的五森林推理合计约 2147 秒。16 个块使用磁盘暂存，最大单块约 2348 万成员；运行修复已支持完成，不是本轮效果退化的证明。
- 原版平均最佳重叠仍高，v1 的 Coverage 仅下降约 0.98 pp，而 F1 下降约 18.66 pp。说明在很多 GT 附近仍有较好掩码，同时输出有效性/实例去重更值得优先检查；它不证明所有掩码边界都正确。

代码审查确定：全林 NMS 先按原掩码做抑制，再按质量优先互斥分配。只要掩码还剩任意点就形成实例，继续沿用分配前的分数。存在“较完整掩码评分后被裁为小残片，仍作为高分实例输出”的机制。**它造成多少 FP，当前 JSON 无法量化；同树查询重复、局部截断、评分误差及表示能力不足都仍可能参与。**

## 下一步：先复用现有输出定位，不重训

新增 `diagnose` 入口，只读取现有 `refined_labels.npy`、`instances.json`、缓存 GT 和最终评价。逐片森林在 CPU 上构造一次 contingency table，复用它评价三个固定的只删最终实例对照：

1. 分配后保留比例 `final_count / count >= 0.5`；
2. 原质量分数 `score >= 0.6`；
3. 分数乘保留比例 `score * final_count / count >= 原质量阈值 0.4`。

记录 TP/FP 中的保留比例、分数及最终最佳 GT IoU 分布，高分 FP 数、严重裁切 FP 数，以及 FP 最佳重叠树是否已被另一 TP 匹配。最后一项是关联证据，不是已证明的重复分类。

这些是依据失败结果设计的事后诊断，GT 仅用于评价；三个过滤决策均只使用保存的分数和点数。只删除最终互斥掩码，**不重放 NMS、不恢复被抢占点、不更新模型**，因此不能用它直接断言新的完整融合流程或架构已有效。若简单删除碎片就明显减少 FP 且保留 TP，优先改分配后有效性判断；若 TP/FP 分数与保留比例均难分，再考虑质量监督与查询唯一性训练。
