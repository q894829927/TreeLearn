## 接法中的问题

V2 原质量目标是 Hungarian 匹配 query 在 argmax 点竞争后所得的完整树 IoU。早期两个 query 可能都给出正确二值掩码，但匹配的那个 query 尚未赢得点；它的质量目标就变成零，另一个未匹配 query 的质量目标也设为零。这会把仍有用的候选一起往低分训练。它是可以用构造案例验证的目标错配风险，是否解释本次全部失败仍要看冻结权重诊断。

原推理还使用 `sigmoid(quality_logit) * mean_positive_mask_probability`。在分数已经被低估时，这会再次降低分数并受到 0.3 门槛过滤。仅有平均分还不能证明所有掩码质量都正常，也不把降低门槛当作最终解决方案。

修正保持模型参数结构和几何/注意力模块不变：

- `quality_target_revision: 2`：质量头预测每个二值候选与已知 GT 的最佳完整树 IoU，独立于 Hungarian 匹配和 argmax 谁先赢得点。好重复候选仍可有高质量；独占归属继续由 ownership CE 监督。未知 anchor 且未被匹配的 query 不作为质量负样本。
- `score_revision: 2`：推理直接用质量预测，不再乘第二次 mask confidence；0.3 质量门槛保持不变。新配置的训练目标版本与推理评分版本必须一致。
- 新增训练日志：预测质量均值、目标均值、匹配候选原始 IoU、互斥后的 IoU、原始合格候选数和互斥合格匹配数。
- 新增推理日志：非空掩码数、质量门槛通过数、实际分数通过数、互斥证据通过数，以及质量均值和 mask confidence 均值。
- 修正版在 500 步增加完整源域验证；F1 <50% 或检出率 <40% 时保存失败信息和固定步数权重并停止，不写入 best，不自动进入后续训练或 Wytham。安全线是防止继续耗时的失败检查，不是成功标准；恢复命令也不会绕过已失败检查。

新增三项服务器回归：好候选尚未赢点时仍得到正质量监督；直接质量分数不重复乘置信度；源域严重崩溃时停止且不能盲目 resume。连同原用例共 15 项，本地未执行。

原 `full.yaml` 仍表示 revision 1，其评分分支保留用于诊断。源码已改变，原失败训练不应直接 `resume`；新训练使用独立的 `score_fixed.yaml` 和 `work_dirs/forest_abc_v2b_s42`，从冻结 V1 20000 步重新初始化，而不是延续已低估评分的 V2。原权重、日志和预测保留。
