# ForestABC：20000 步权重的少量块阶段诊断

## 为什么先做这一步

Wytham 的后验诊断已复现原指标：877 棵 GT 中，基线检出 596 棵，ABC 检出 307 棵；基线检出而 ABC 丢失 298 棵，反向恢复 9 棵。570 棵漏检中，430 棵属于最佳 IoU 预测召回至少一半、纯度不超过一半。覆盖多棵 GT 各至少一半点的最终预测从 86 个增加到 189 个。主要错误是最终实例混合，但这些结果不能确定原始 decoder 输出和后处理各自的责任。

当前缓存的竖向跨度分组中，<10 m 的 GT 共 270 棵。正确检出的净损失 289 棵中，234 棵来自跨度 >=10 m 的实例。因此补小树监督仍值得做，但不能单独解释和解决全部退化。竖向跨度是 max(z)-min(z)，不等于地面归一化树高。

新工具只重放少量原始块，不训练模型，不修改现有预测。模块、配置和阈值保持原样，先决定下一版应该改实例掩码学习还是候选选择/合并。

## 固定选择与核对

[stage_audit.py](../../tools/forest_abc/stage_audit.py) 从上一轮 `trees.csv` 固定随机种子分层抽取最多 12 棵树：4 棵 10–20 m 低纯度丢失实例、2 棵 >=20 m、2 棵 <10 m，以及 4 棵成功检出对照。某层不足时按实际数量报告，不重复抽取。GT 只用于选择诊断案例和事后量度，不进入模型输入。

每棵树重放距离其标注点 XY 质心最近的原始网格块，并补充其整林最佳预测的来源块。去重后最多 24 块，使用原始块编号、采样种子和 98,304 体素上限。它是按错误富集的局部分析，不是随机测试集，不能作为整林 F1 或推进新模型的依据。

运行前核对：完整外部结果与后验报告都是 20000 步；冻结 checkpoint 的 SHA256 与原评估一致；checkpoint 训练签名、模型/管线代码和推理配置未变化；后验报告记录的数据文件时间和大小仍一致。重放结束再次检查输入文件。

训练继续保持停止。开发机只完成静态检查，没有运行模型或下列测试。


脚本打印 `PLAN`、`REPLAY x/y` 和每块完成统计，始终在前台。默认最多保存 1 亿条候选点成员记录，int32 时掩码数据最多约 400 MB，另加文件头/CSV/JSON。超出预算会报错，不静默截断。临时块掩码沿用磁盘溢出机制。前置 CPU 扫描和每块阶段统计也需要时间，不能用原先单块 GPU forward 的时间直接估算总耗时。

可加 `--plan-only` 仅生成 CPU 选块计划，不加载 checkpoint 或模型。默认结果目录为 `work_dirs/forest_abc_v1_s42/stage_audit/step_020000/wytham_vox0.1/`，不会覆盖完整外部评估。运行完整诊断后先查看 `brief.json`。

## 输出与解释

- `plan.json`：所选树、诊断分层、原始块编号；`progress.json`：已完成块数。
- `brief.json`：每棵目标的阶段分类、各阶段最佳 IoU、各层最佳 IoU，以及重放元数据不一致记录。
- `block_targets.csv`：每块每棵目标的输入细胞、前景/ISA/query 覆盖，以及原始掩码、质量筛选、最小点数筛选、局部 NMS 后的最佳候选。
- `layer_targets.csv`：初始 head 和后续每个 decoder 层的最佳掩码质量。层标签包含 cross-attention/MFA 更新，但同层还含 self-attention 和 FFN，不是模块消融。
- `block_*/queries.csv`：各 query 的分数、点数、GT 混合和局部保留情况；`query_*.npy` 保存局部 NMS 后的候选全局点索引。
- `summary.json`：完整案例、来源、层/阶段结果，以及与已保存全局实例之间的冲突证据。

细点统计与实际最近邻投影一致，用 sparse 计数计算，不创建 Q×整块细点的巨大矩阵。预测体积与交集只计非负 GT 点，IoU 分母使用完整标注树的点数，严格 >0.5 才算有合格提案。裁剪只看到一部分树不会把它当作完整树来乐观计分。没有合格原始提案时，至少要有一个覆盖目标 95% 点的重放块才分类为“所抽块未产生好掩码”；否则标为上下文不足。有合格完整树 IoU 的部分裁剪提案仍计入真实可用证据。

若在某阶段已经没有合格候选，则分别归为原始掩码不足、质量筛选、最小点数或局部 NMS 丢失。若局部尚有合格候选而已保存整林结果差，则只归为“局部可用、整林最终差”，不自动宣判全局 NMS。工具进一步检查重放出来的较高分、已被整林接受的原始掩码是否与好候选冲突，或已被接受的好掩码在互斥分配后 IoU 是否退化。

全局检查仍有限制：未重放其余原始块；只检查所抽块中可见的已接受实例；没有冲突证据不能排除全局后处理问题。已接受实例用分数/点数/bbox 与原记录核对，原始掩码已删除，无法证明逐点 bitwise 一致。出现 `replay_metadata_mismatches` 时必须先排查重放差异，不把冲突记录当成确定归因。

query 覆盖用最近邻输出细胞是否包含目标点及其多数 GT 标签统计，并非训练时精确体素多数标签或实际代表点标签。它可定位覆盖线索，不能单独证明某棵树本来应由哪个 query 负责。任一层最佳 IoU 变化也只描述这次前向传播，不能证明某模块的消融因果。

## 结果如何决定下一版

若合格提案在原始/后续 decoder head 就很少，优先加强实例归属竞争、几何中心约束、尺度与密度增强，并评估恢复完整 cross-attention、让 MFA 作为轻量残差。若原始提案好而质量/局部筛选丢失，先修对应评分或抑制规则。若有高分混合掩码冲突或互斥分配退化的证据，先处理全局实例选择，不以重新训练代替已定位的合并问题。第一轮局部阶段诊断后收敛到一个完整修改方案，不自动启动多组消融。
